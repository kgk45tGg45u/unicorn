# What changed in each release

In plain words, for members and operators. A release that carries an approved change to the hard frame names its ticket (`T-…`) here, and an operator records it with `record_release` (P07.T06). Version tags look like `v0.9.0`. Every release goes to staging first (deploy/README.md, "Releases").

## Not released yet

The first full version, built in phases 0 to 15 (see PLAN.md): members and their contract, the UNIQ books, units and working councils, the catalogue and the labour values, the market, tickets with random confirmers, votes and delegates, the trade fund, the monthly close, outside sales, the yearly plan, shipping, unions and councils, security and privacy, and the files for the server.

## v0.0.1 — the first install on the box

Nothing new. It is the version that is put on staging (and then on production) the first time, to try the steps in `deploy/README.md`. `v0.0.2` is then used to try a release and the rollback. Delete these two entries when the first real release is made.
